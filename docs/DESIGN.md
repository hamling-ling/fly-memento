# 記憶する虫ロボ：縮約キノコ体、シミュレーション、UNO Q

fly-memento の設計メモ。式の出典と、測っていない定数の置き場所。コードから書き下した式は [MODEL.md](MODEL.md)。研究の経過は [SUMMARY.md](SUMMARY.md)、ポスターは [poster/poncho_e.html](poster/poncho_e.html)。

## 参照したもの

- **fly-car**（https://github.com/hamling-ling/fly-car ）。UNO Q の Linux 側 Python がカメラとニューロンを約 50 Hz で進め、マイコンのスケッチが車輪を回す。右 D3、左 D5。RPC は Arduino RouterBridge。車輪間隔 0.12 m、巡航の目安 0.06 m/s（`MOVE_MPS`）。膜の刻み `TICK_S` = 0.02 s、カメラの読み `COUNT_S` = 0.1 s。このリポジトリの `robot/` はその分け方を継いでいる。接近の符号（反対側の車輪が速くなる）も同じ。
- **UNO Q**（https://docs.arduino.cc/hardware/uno-q/ ）。MCU は STM32U585、Cortex-M33、最大 160 MHz、Flash 2 MB、SRAM 786 kB、FPU。MPU は QRB2210 の A53、Debian。

脳のコードは `brain/` にあり、`sim/` と `robot/` が同じクラスを呼ぶ。実機にだけあるのはカメラの色、バツと自動手順の画面、サーボのパルス、学習した脳の JSON である。

同梱の振動子 4 セット（`brain/sets.py`）は、111 セットの抽選そのものではない。圧縮 1 の時計で周期がおよそ 5–15 秒（生物分と同じ数値。標準の 5 では壁時計がその 1/5）、ε=0.1 で相関が約 0.95、ε=0 で相関がほぼ 0、一致の比 C(ε=0)/C(on) が約 0.3、になるように選んだ。ドーパミンは、ε=0.1 の自由走行の平均で割って正規化する。

### 時間圧縮

`compression` は、ロボットの 1 秒が何生物分に当たるか。つまみは `brain/constants.py` の `DEFAULT_COMPRESSION` ひとつで、実機の `config.COMPRESSION` はこれを読む。標準は 5。1 秒が 5 生物分、24 時間は 4.8 分。圧縮 1 は研究ランの K=60（1 分が 1 時間）と同じ時計である。

記憶の ODE に加え、振動子の τ、適格痕跡、罰の減衰、不応期もこの倍率で縮む。生物時間の軌道は圧縮 1 と揃う。50 Hz の一歩は、生物時間の刻みが 0.02 分を超えないように内側で割る。圧縮 5 なら 5 片で、各片の h/τ は圧縮 1 の 0.2 のままである。アリーナの体は圧縮 1 と同じ歩幅で進み、試行の壁時計だけが 1/圧縮になる。

訓練の 1 周は生物で CS+ 20 分 + CS− 20 分。壁時計ではこれを圧縮で割る。圧縮 5 なら赤 4 秒、青 4 秒。間隔の門 10 生物分は 2 秒、推奨の休息 15 生物分は 3 秒。生物の 40 分はハエの 1 試行より長い。これは圧縮 1 のときからの長さで、圧縮では縮めない。

## 計算量（`brain/budget.py`）

原型の見積もり（`docs/results/cost.txt`、別のマシンで 1 ステップ約 140 µs）。

- 約 9600 flop / 20 ms（`flop_budget` の合計は 9558）。50 Hz で約 0.5 MFLOP/s。160 MHz の M33+FPU を 1 flop/cycle・SIMD なしと置くと、おおよそ 0.3%。桁の確認であって、サイクル精度の見積もりではない。この勘定は圧縮による内側の分割を掛けない。標準の 5 では、その 20 ms のあいだに振動子と記憶を 5 回更新し、PN から車輪までは 1 回である。
- 状態は約 4.5 kB。S/A/L が 3×100 の float32 で 3.6 kB、爪のインデックスが 400 B。SRAM 786 kB の 1% 未満。
- float32 で足りる。FPU があるので Q15 にはしていない。
- 最初の実装は MPU の Python。MCU へ移すのは、時刻を固定したいデモの次の段階。

## 実機への割り当て

- **色（CS）。** 赤が CS+（罰）、青が CS−（安全）。幅 10 cm ほどのパネルを、スタートから約 0.5 m。切り替えは手でよい。
- **色の読み。** Linux 側のカメラ。数え方は fly-car と同じで、OpenCV の HSV、色相は度（OpenCV の 2 倍）、`color_thresholds.json` の赤ラップと青の閉区間、フレームの 0.2% 未満の連結領域は捨て、幅 320 に縮めてから数える。左右の眼は画面の左 65% と右 65% で中央が重なる。既定の門は fly-car がこのカメラで合わせた値（赤は色相 322° 以上、彩度 100、明度 120。青は 180–220°、彩度 160、明度 70）。色相 0° の純赤と 240° の純青はこの窓の外である。脳へ渡す符号は、窓を通った赤が `CS_PLUS_HUE`（0°）、青が `CS_MINUS_HUE`（240°）で、測った色相ではない。眼の割合が `fraction_floor`（0.05）未満はログにだけ残り、PN には渡さない。OpenCV が無い、またはカメラが開けないときは、画面は暗いゼロのまま動き、バツだけは効く。I²C の RGB センサは未選定。
- **罰。** スマホのバツ。同じ LAN からポート 8000。`robot/python/train_ui.py` が標準ライブラリでページを出す。押下は次の 20 ms ステップで `Brain.punish` になる。適格痕跡は 2 生物分で減衰する。標準の圧縮 5 では壁時計 0.4 秒なので、色が見えているあいだに押す。不応期は 1 生物分（標準なら 0.2 秒）で、期間内の要求は捨てる。周が閉じていても S には入る。ウェブ画面にした理由は、UNO Q の web_ui ブリックがソケット用のフロントを別途要することで、ボタンにはプロセス内の HTTP の方が短い。ブリックへ載せ替えるなら、`/punish`、`/cycle`、`/flags` に加え、手順の開始・中断と記憶の保存・読み込みもメッセージにすれば足りる。
- **周。** 「周を始める / 周を終えて休む」が、シミュレーションの `end_cycle` に対応する。休息が 10 生物分以上だと、次の周の終わりから 10 生物分、LTM の窓が開く。1 周目は隙間が無く、窓は開かない。集中の休息は 2 生物分で門を下回る。標準の 5 では 0.4 秒である。疲労 φ が立ち、窓は開かない。門の 10 生物分は、標準では壁時計 2 秒である。
- **自動の手順。** ページは分散、集中、1 回を走らせる。長さは `PROTOCOL` の生物分を `DEFAULT_COMPRESSION` で割った壁時計である。赤の相だけ、赤が `in_view`（1 生物分）続いてから `punish_every`（1.2 生物分）ごとに罰を要求する。青は要求しない。周が開いているあいだ、つまり赤と青では、S の受動減衰とドーパミン忘却が止まる。ボタンの順は [robot/README.md](../robot/README.md)。
- **学習の保存。** 学習した脳は JSON で `~/fly-memento-data/memories/` に残る。`FLY_MEMENTO_DATA` があれば、その下の `memories` である。ファイルは S / ARM / LTM に加え、ケニヨン細胞の配線、振動子、周の時計、疲労、罰の回数、圧縮を持つ。自動手順は「終了」で `auto-<種類>-時刻.json` を書く。同じファイルを後から読み戻せる。`scripts/deploy_fly-memento.sh` はこのディレクトリを消さない。MCU のフラッシュには書いていない。「終了」より前に電源が落ちた分は、その場で保存していない限りファイルにならない。
- **スイッチ。** ε と振動子のオンオフはページのチェック。脳のフラグをその場で変える。
- **マイコン。** 50 Hz で届くパルスを D3/D5 のサーボ信号にする。3 秒届かなければ止める（watchdog）。左の配線は fly-car と同じく反転。m/s → パルスの倍率は fly-car のまま、床での再計測はまだ。
- **まだ無いもの。** バンパ（D2 は空）、LED マトリクスへの DAN 表示。

### 配置とログ

PC からボードへ SSH の鍵で入れる。ボード側は Debian の Arduino UNO Q で、`arduino-app-cli` と Docker が入っている。送り先の初期値は `arduino@uno-q-1.local`、置き場所は `~/ArduinoApps/fly-memento`。`scripts/deploy_fly-memento.sh` がアプリを止めて、`robot/`（`app.yaml`、`python/`、`sketch/`、`assets/`）をコピーし、`brain/` を `python/brain` に置いてから起動する。`app.yaml` と `sketch/` が前回の `~/ArduinoApps/fly-memento/.sketch-hash` と同じなら `.cache` を残す。スケッチを作り直すときは `--rebuild`。SSH せずに中身だけ見るときは `--dry-run`。

```bash
scripts/deploy_fly-memento.sh
scripts/deploy_fly-memento.sh arduino@other.local
scripts/logs_fly-memento.sh
```

ログは PC の `logs/fly-memento-日時.log` に残る（`logs/` は git に入らない）。罰、MBON の 3 区画、そこから出た回避、ARM、LTM、車輪パルスが、止まっているときは 1 秒に 1 行、動いているあいだは 0.1 秒ごと。バツのページは同じ LAN の `http://<UNO Q のアドレス>:8000/`。起動ログに `バツ画面` とそのポートが出る。

## シミュレーションのプロトコル

`python -m sim`。圧縮は `DEFAULT_COMPRESSION`（標準 5）。試行と休息は生物分で書いてあり、ロボット時間はそれを圧縮で割る。体の一歩は圧縮 1 のままなので、道のりは揃う。

- 分散：5 周、周のあいだ 15 生物分。集中：5 周、あいだ 2 生物分。
- 各周は CS+（バーに当たると罰）20 生物分、CS−（バーなし）20 生物分。
- テストは未学習、1 h、3 h、24 h、72 h。ロボット時間は生物分を圧縮で割ったもの（圧縮 5 なら 12 秒、36 秒、4.8 分、14.4 分）。脳をコピーしてから走らせ、選択が付いたら止める。PI = 100 ×（CS− を選んだ数 − CS+ を選んだ数）/ 選択数。正が「罰の色を避ける」。

アーカイブ（`sim/figure.py` の `ARCHIVED`、COI、10 seed × 40 試行）では 72 時間の PI が分散 69.7、集中 44.7 で、ここには約 70 と約 45 と書く。研究ログでは、ε=0 が分散の LTM を落とし、集中にはほぼ効かず、振動子オフは LTM が 0 で 72 時間が集中に近い。既定の `python -m sim` は種子 4 × 試行 12、圧縮 5 で、点線がこのアーカイブ、実線が今回の実行である。色を止めた照合では、圧縮を 5 にしても分散は LTM、集中は ARM のままで、集中の LTM は 0 である。
