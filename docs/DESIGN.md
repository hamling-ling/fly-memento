# 記憶する虫ロボ：縮約キノコ体、シミュレーション、UNO Q

fly-memento の設計メモ。式の出典と、測っていない定数の置き場所。研究の経過は [SUMMARY.md](SUMMARY.md)、ポスターは [poster/poncho_e.html](poster/poncho_e.html)。

## 参照したもの

- **fly-car**（https://github.com/hamling-ling/fly-car ）。UNO Q の Linux 側 Python がカメラとニューロンを約 50 Hz で進め、マイコンのスケッチが車輪を回す。右 D3、左 D5。RPC は Arduino RouterBridge。車輪間隔 0.12 m、巡航の目安 0.06 m/s（`MOVE_MPS`）。膜の刻み `TICK_S` = 0.02 s、カメラの読み `COUNT_S` = 0.1 s。このリポジトリの `robot/` はその分け方を継いでいる。接近の符号（反対側の車輪が速くなる）も同じ。
- **UNO Q**（https://docs.arduino.cc/hardware/uno-q/ ）。MCU は STM32U585、Cortex-M33、最大 160 MHz、Flash 2 MB、SRAM 786 kB、FPU。MPU は QRB2210 の A53、Debian。

脳のコードは `brain/` にあり、`sim/` と `robot/` が同じクラスを呼ぶ。実機にだけあるのはカメラの色、バツのウェブ画面、サーボのパルスである。

同梱の振動子 4 セット（`brain/sets.py`）は、111 セットの抽選そのものではない。周期が数秒から十数秒、ε=0.1 で相関が約 0.95、ε=0 で相関がほぼ 0、一致の比 C(ε=0)/C(on) が約 0.3、になるように選んだ。ドーパミンは、ε=0.1 の自由走行の平均で割って正規化する。

### 時間圧縮

`compression` は、ロボットの 1 秒が何生物分に当たるか。標準は 1。研究ランの K=60（1 分が 1 時間）と同じ時計である。5 にすると 1 秒が 5 生物分。

記憶の ODE だけがこの倍率で進む。振動子の τ はロボット秒のまま。だから振動の 1 周（約 10 秒）は、圧縮 1 では約 10 生物分に見える。これは仮定である。

訓練の 1 周は、シミュレーションでは CS+ 20 秒 + CS− 20 秒。生物では 40 分。ハエの 1 試行より長い。これも圧縮の副作用である。

## 計算量（`brain/budget.py`）

原型の見積もり（`docs/results/cost.txt`、別のマシンで 1 ステップ約 140 µs）。

- 約 9600 flop / 20 ms。50 Hz で約 0.5 MFLOP/s。160 MHz の M33+FPU を 1 flop/cycle・SIMD なしと置くと、おおよそ 0.3%。桁の確認であって、サイクル精度の見積もりではない。
- 状態は約 4.5 kB。S/A/L が 3×100 の float32 で 3.6 kB、爪のインデックスが 400 B。SRAM 786 kB の 1% 未満。
- float32 で足りる。FPU があるので Q15 にはしていない。
- 最初の実装は MPU の Python。MCU へ移すのは、時刻を固定したいデモの次の段階。

## 実機への割り当て

- **色（CS）。** 緑が CS+、黄が CS−。幅 10 cm ほどのパネルを、スタートから約 0.5 m。切り替えは手でよい。
- **色の読み。** Linux 側のカメラ。閾値は `robot/python/color_thresholds.json`。左右の眼の占有率が、`brain.pn_code` への 2 灯になる。OpenCV が無い、またはカメラが開けないときは、画面は暗いゼロのまま動き、バツだけは効く。I²C の RGB センサは未選定。
- **罰。** スマホのバツ。同じ LAN からポート 8000。`robot/python/train_ui.py` が標準ライブラリでページを出す。押下は次の 20 ms ステップで `Brain.punish` になる。適格痕跡はロボット秒で減衰するので、色が見えているあいだに押す。ウェブ画面にした理由は、UNO Q の web_ui ブリックがソケット用のフロントを別途要することで、ボタン 1 個にはプロセス内の HTTP の方が短い。ブリックへ載せ替えるなら、同じ JSON（`/punish`、`/cycle`、`/flags`）をメッセージにすれば足りる。
- **周。** 「周を始める / 周を終えて休む」が、シミュレーションの `end_cycle` に対応する。休息が 10 生物分以上だと、次の周の終わりに LTM の窓が開く。集中（2 秒）は疲労 φ が立ち、窓は開かない。
- **スイッチ。** ε と振動子のオンオフはページのチェック。脳のフラグをその場で変える。
- **マイコン。** 50 Hz で届くパルスを D3/D5 のサーボ信号にする。3 秒届かなければ止める（watchdog）。左の配線は fly-car と同じく反転。m/s → パルスの倍率は fly-car のまま、床での再計測はまだ。
- **まだ無いもの。** バンパ（D2 は空）、LED マトリクスへの DAN 表示、電源断をまたぐ LTM の保存。圧縮を 1 のまま本当の翌日まで置くなら、L と時刻を eMMC かフラッシュへ書く必要がある。

## シミュレーションのプロトコル

`python -m sim`。圧縮は 1 に固定してある（表の時計を崩さないため）。

- 分散：5 周、周のあいだ 15 秒。集中：5 周、あいだ 2 秒。
- 各周は CS+（バーに当たると罰）20 秒、CS−（バーなし）20 秒。
- テストは未学習、1 h、3 h、24 h、72 h。ロボット時間では 1 分、3 分、24 分、72 分。脳をコピーしてから走らせ、選択が付いたら止める。PI = 100 ×（CS− を選んだ数 − CS+ を選んだ数）/ 選択数。正が「罰の色を避ける」。

アーカイブ（COI、10 seed × 40 試行）では 72 時間の PI が分散 約 70、集中 約 45。ε=0 は分散の LTM を落とし、集中にはほぼ効かない。振動子オフは LTM が 0 になり、72 時間は集中に近い。今回のコマンドはその再実行で、セットの数と試行数は少ない。痕跡の桁（分散は LTM、集中は ARM）が先に合うことを確認してある。
